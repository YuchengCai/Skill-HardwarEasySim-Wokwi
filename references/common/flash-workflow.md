# 本地烧录与工具链（序列4/文档47）

本 skill 本期从共享入口接通**用户已委托**的本地编译/烧录。云端浏览器只展示连线；USB 枚举、串口选择、固件上传必须由具备本机设备访问能力的 Agent 执行。纯绘图/选型/改图不需要 Arduino CLI、板卡核心或 USB 设备。

## 触发与检查

| 现场 | 动作 |
|---|---|
| 加载/选型/绘图/改图 | 直接处理；不安装、不枚举、不上传 |
| 用户委托本地编译或烧录 | 先确认执行环境在用户本机、能调用命令；查已配置路径、PATH、常见位置，运行 `arduino-cli version`；可用直接复用 |
| 找不到 CLI | 简短说明用途，给「安装并继续 / 指定已有路径 / 稍后」三选一；已覆盖该依赖的安装授权可沿用；安装前说明来源/位置/权限；优先用户范围；探测阶段保持用户 PATH/配置/核心目录原样；安装后重跑版本检查再接回任务；离线/无权限/安装失败报告实际原因并保留工程与接线指导 |
| CLI 存在、编译依赖不齐 | 由已确认板型得 FQBN；按**供应商+架构**精确检查 core；核对项目实际需要的库；向用户合并说明需补齐的依赖，在授权范围内安装后再编译；编译失败给具体错误并停在编译阶段 |
| 展示接线图、用户已委托烧录 | 用合并确认说明：写哪版程序、目标板型、会替换现有程序；用户有接线疑问先处理；同意后再检测设备 |
| 枚举设备 | 零块：提示接板后复查；权限不足/串口占用：报告实际原因；唯一且与目标匹配：直接写入一次；多块：列板型+端口让用户选；单块型号不明/不符：核实。写入前复核设备与固件，变化重新确认 |
| 上传结束/中断 | 用上传器实际调用、目标、产物与返回结果判定：已编译 / 等待接板 / 上传成功 / 上传失败 / 结果未知；结果未知先核实，避免重复写入 |

## 板型映射（本期）

| 实物 | FQBN | 说明 |
|---|---|---|
| 经典 Uno | `arduino:avr:uno` | 端到端必验基准 |
| 经典 Nano | `arduino:avr:nano` | 保留实际需要的处理器/引导程序选项（如 `cpu=atmega328old`） |
| Mega | `arduino:avr:mega` | 与 Nano 共用 avr 核心 |
| 经典 ESP32 DevKit V1 | `esp32:esp32:esp32` | 独立核心；编译产物集合与上传器消费同次构建产物；**不要**固定报告 .hex（ESP32 用 .bin） |
| 其他板型/未知 | — | 走未知分支：报告不支持自动映射，给出手动 FQBN/命令入口 |

## 设备识别（逐端口证据，不猜）

1. 读本机 CLI 能提供的逐端口板型候选与端口属性；Unknown 或证据冲突时补查 USB 硬件号（VID/PID）、产品描述、设备标识；优先结构化枚举，降级查询也必须关联具体端口；序列号可辅助区分设备，型号仍需板级证据。
2. 候选与此前确认的实物、项目目标逐一对照并保留证据来源。CH340/CH341、CP210x、FTDI 只提供串口桥线索。**移除「Unknown 默认 Uno」「取第一张图例」「适配器直接指定 Uno」的捷径。**
3. 唯一设备的可靠板级识别与已授权目标一致才直接继续；仅有通用桥线索、多个候选或与项目冲突时，给有依据的板名选项（标端口与推荐依据）并附「其他／不确定」。例：「COM5 检测到 CH340。工程选的是经典 Nano，请确认接在这里的是哪种板：经典 Nano／其他板／不确定。」无型号候选时给「查看板上印字／提供商品名或照片／稍后」，不要求填 FQBN。
4. 多设备可让用户选端口或拔插目标板后重新枚举；型号变更时重新核对接线、目标参数与写入意愿。

## 工具入口

`scripts/flash-arduino.js`（零依赖 Node 封装，供自动化与回归；真实调用 arduino-cli）：

```bash
node scripts/flash-arduino.js --detect                 # 查找 CLI 并打印版本
node scripts/flash-arduino.js --list                   # 逐端口候选（JSON 优先）
node scripts/flash-arduino.js --board uno --compile <dir>
node scripts/flash-arduino.js --board uno --port COM5 --dir <dir> --upload --confirm
node scripts/flash-arduino.js --simulate --board uno --dir <dir> --upload   # 只打印计划，不执行
```

- 未给 `--confirm` 时 `--upload` 拒绝执行（exit 3），用于保证「先确认再写板」。
- `--simulate` 不调用 arduino-cli、不访问设备，输出阶段与命令计划，供纯绘图/回归证明调用次数为 0。
- 失败/未知结果按上表区分，不把脚本正常退出当作已上传。

## 验收（文档47）

用可记录调用的本地工具替身覆盖：纯绘图（安装/枚举/上传次数均为 0）、CLI 可用但不在 PATH、缺 CLI 后的三选择、缺目标架构但已有同厂其他核心、缺库、安装失败、仅云端、设备访问受限，以及零板/单板/多板/目标变化。另在有板且用户明确授权的本地环境完成一次真机验收，记录板型/端口/固件版本/上传器结果；没有真机证据时标记待验。
