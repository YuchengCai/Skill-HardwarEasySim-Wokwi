## 3. 已验证的设计规则（照做）

1. **离体方向 = 引脚开放侧**：底边向下、顶边向上、左边向左、右边向右。左/右边缘引脚**必须先水平离开本体**（否则穿自身 110px）。
2. **离体槽 12px（SLOT_STEP）+ 本体避让**：可用窗口 = 同排邻件边缘外 8px；**放不下时整梯均匀压缩**（`room/(cnt-1)`），绝不塌到同一个 x。
3. **同源束线序不拧**：同(元件,边)的线按引脚 y 降序分配槽/车道（下面引脚→近侧）。
4. **电源基础设施按网选**（来自用户黄金样本）：
   - 参与者 ≤2（1 馈 + 1 消）→ **单列即网**：馈电占列首孔（a，多族依次 a/b/c）、消费者占列尾孔 e，免轨免跳线；
   - 多消费者 → **列总线 + 每族一根跳线到轨 + 板端部馈电**（n=25，靠板侧）；
   - 上缘轨(bp)供电：tp 空闲时 **tp 端部馈电 + 末端桥 tp↔bp**（同极双轨合法）；否则绕边馈电。
   - **严禁** tp↔bp 桥接不同电源网（5V 与 3.3V 会短路——曾犯）。
5. **列半区跟目标轨**：下缘轨(tn/tp)→t 半区(a-e 孔)、上缘轨(bp)→b 半区(f-j 孔)。
6. **跳线孔预留**：t 列保留 a、b 列保留 j；消费者不占。
7. **直落式入孔**：落孔竖向无遮挡时走 3 段（escape→v→h→微斜），不遮挡才用 5 段。
8. **模块带锚定面包板列中心**（T2：板在左、面包板在右；板那一列上方无可连对象）。
9. **列位/转弯位避让更低行模块的 x 带**（否则落孔竖段穿模块本体）。
10. **走线方向即语义**：起点=真空中可离体端，终点从目标引脚开放侧进入；bb→bb 桥线豁免方向检查。
11. **转角柱（turn posts，本轮新增的核心）**：
    - 所有机动竖段（离体槽 / 进脚柱 / 落孔柱 / 绕板柱）都落在 **14px 网格**上（`POST_STEP`），柱与柱/固定桩最小间距 6px（`POST_CLEAR`）；
    - 占用判定必须**带 y 区间**（`VSEG`）：轨位每 9.6px 一个，若按"全 x 唯一"任何 5 连柱都会撞轨被挤飞（实测 mux 进脚柱从 434 被挤到 336）；
    - 分配顺序 = 优先级：绕板柱（贴板）→ 进脚柱（贴目标件）→ 离体槽（贴源件）→ 落孔柱（最自由，最后挑）——逐线阶段只查表；
    - 束内整梯平移（一步 14px）而不是逐柱挪 2px。
12. **直落优先（本轮新增）**：能"一拐到位"就不要走车道——
    - 底边板脚：离体 x 已在板带外 → `bottomDrop`（v→h→v，3 转角），否则绕板（5 段）；
    - 模块→模块：离体竖段 + 进脚横段都不穿本体、且进脚方向对得上开放侧 → `modDrop`（2 转角）；
    - 进轨：在引脚 y 上直接横到轨位再竖落 → **1 转角**（旧做法先下车道再横 3.6px 再落 = 3 转角）；
    - 离体横段与"横到轨位"同向且只差 <8px 时并成一段（消掉 S0 那种 +54 再 -3.6 的 180° 回勾）。
13. **多族单列馈电按板脚 x 升序发 a/b/c 字母**：x 最小的馈电拿最低孔行，它的横段最长，放最低才不会横穿另一族馈电的竖段（N1 实测：字母顺序搞反 → 交叉 3→4）。

**① ~~形态目标自相矛盾~~（⚠️ 2026-11-08 二次审计后大幅修正，原结论不成立）**：

1. **顶开放引脚的长下钻穿自身本体**：I2C 器件的引脚离顶边（5.8px）比侧边（7.2px）近 →

2. **跨网同字母孔入口共线**：SDA/SCL 同字母孔（如 17t.c / 18t.c）同一 y 入口横段重叠 →
   每个信号中继按序号给入口 y 错位 2.4px（`hole.yOff`）。

## 6.12 U3 手理线对比：可读性判据（2026-11-09，用户手改版 U3-user）

**结论先行**：用户手改版**孔位分配与我们逐孔相同**（SDA 17t.c/d/b、SCL 18t.c/d/b、5V 15t.b/d/c、GND 16t.b/d/c、
馈电 a 孔），差异全部在**长横段所在行与末端进入方式**。数字对照：

| | 我们 U3-v2out | 用户 U3-user |
|---|---|---|
| 硬冲突 | 0 | 0 |
| 交叉 | **13** | **24**（用户接受更多交叉） |
| 转弯/线 | 2.33 | 2.78 |
| **端点遮挡**（`_endpoints.js` A 项：他线内部从孔端点 <4px 擦过） | **23** | **9** |

→ **用户的优先序：端点可区分性 > 交叉数**。交叉只要垂直清晰就可读；端点被他线擦过/同排覆盖
会让两根线"看起来像接了"——这是语义级错误，不是美观问题。我们此前的验收轴（硬冲突/交叉/转弯/线长）
完全没有这一项，导致"数字更优但观感更差"（Goodhart：优化了代理指标）。

**提取出的四条约定（待引擎实现）**：
- **C1 末端可读性**：任一孔端点 4px 内不得有他线内部穿过；末段不得与其他孔端点同排覆盖。判据脚本 `_endpoints.js`。
- **C2 孔序-末端形态成列耦合**：一列接收两侧来线时，近侧线水平入口（本行），
  **远侧线垂直下落入口**（长横段抬到孔行上方，再在列 x 附近竖直进入）——同列相邻孔不得同侧同形。
- **C3 长横段跨行**：长横段不得落在任何孔行上（抬到孔行之间/之上），否则与孔行视觉融合。
- **C4 组间留白**：器件间距要保证每根线的下降段有独立间隙；列组之间留空。

**根因**（用户假设成立）：我们的 bus 入口形态 = "先降到孔行 y，再横进孔"——为转弯数/车道对齐优选，
但把长横段恰好放在孔行上，必然与同列/邻列端点相撞；用户的做法是"长横段抬走 + 竖直落孔"。

**现状基线（端点遮挡 A 项）**：U1 3｜U2 5｜U2a 5｜N1 0｜**U3 23**（信号扇出新形态最暴露此问题）。

**已实现（同日第三轮，C2+C5+C3 一次落地，`readability` 门控：仅在 intent 声明 `routing` 时启用）**：
- **C5 列距**：同电路列间 ≥3 空列（无解时退回最近列）；
- **C2 孔序**：`assignLetters()` 按进入侧分组（左侧来线从低孔起/远源取最低，右侧从高孔起/近源取最高，
  中间富余自然留 1 孔缓冲）；
- **C3 末端**：bus 入口横段抬到孔行之间（`stageY = hole.y - 14.4`，逐线 `regHorizY` 错 y 防共线），
  再**竖直落孔**（落孔 x 按孔字母微错位 1.6+li*0.9，防相邻端点接触）；馈电同样处理。

**实测（U3）**：端点遮挡 **23 → 7**（优于用户手改 9）｜交叉 13 → 32（其中 ①拓扑不可免 22、③仅 10）｜
转弯 2.33 → 2.89｜hard 0。**U1/U2/N1/U2a 数字不变**（未声明 routing → 规则不启用）、回归 18/18。
**结论**：可读性轴净赢、交叉代价可接受；交叉里 22 处是模块引脚顺序固有的（换元件左右序才能动），
真正可再压的只剩 10 处。**三条规则是一体的**（C2/C5 单独做只到 23→17，C3 才是承重件）。

## 6.14 手修失败 → "乱"的根因定位（2026-11-09 晚）

用户尝试手修分块版后反馈："走线乱糟糟的，各种重叠穿线，可能需要整个重新调整位置布局"。实测归因：

1. **模块排列穷举（6 种全跑）**：当前顺序已是最优（32/2.89/2 端点），其他排列更差（最高 48 交叉、
   2 处硬冲突）→ **模块顺序不是 U3 的杠杆**；
2. **C8（横段全部搬到 bb 面上方）**：端点遮挡 **0** ✓、硬冲突 0，但交叉 45；
   分类 **①36** ②0 ③9 —— 结构性交叉翻倍，根因 = **列的左右顺序与模块内引脚序不对位**：
   横段在面外后，每条横段都会穿过列在其跨度内的所有竖落段；列序错 1 位就多一批结构性交叉；
3. **对照用户手画版（31 交叉、面干净）**：其列序 SDA@1(545)/SCL@8(477)/VCC@14(420)/GND@20(362)
   = **引脚序的镜像**（模块内引脚最左的 SDA 配最右的列；引脚最右的 GND/VCC 配最左的列）；
   我们按"块就近网均值"分配 → 列序为 SCL/5V/GND/SDA，与引脚序不对位 → 多 14 处结构性交叉。

**下一步（精确规则）**：**列序 = 网内消费者"落点 x 均值"的镜像序**——先算每个网的全部消费者
`approachXOf()` 均值，按均值降序把块从右往左分配（均值最大的网拿最右块）。
预期：交叉 45 → ~31（①回到 22 水平），端点维持 0，面保持干净。

**已做（同日第四轮）**：
- 列序穷举 24 种（`V2_NETORDER` 钩子）：最好 41、最差 53——**列序是杠杆但不是全部**；
- 默认列序定为「电源网最左、信号中继按声明序向右」（`GND,5V,3.3V,…,SDA,SCL`）→ **交叉 45 → 37**；
  变体实测：SDA/SCL 互换 41、GND/5V 互换 39 → 37 是已试最优；
- **端点遮挡 0、硬冲突 0、转弯 2.89 保持**；U1/U2/N1/U2a 不变（63/50/3/38）、回归 18/18；
- 与用户手画版（31/0/2.39）仍差 6 个交叉——剩余差距不在"模块顺序/列序"两个离散自由度，
  指向**连续的几何参数**（模块 x 铺开度、板/bb 对齐、模块-bb 间距）：下一步做**布局参数搜索**
  （用快速生成+裁判对若干组几何参数自动评分择优），而不是再猜单个规则。

## 6.16 簇分配（B）+ 手画版复现实验（2026-11-09 晚）

**B 贪心簇分配（已实现）**：每个网按顺序挑块，代价 = Σ 消费者走线长度 + 60×(与已画网竖落的交叉估计)
——把用户"一类一类画、后面避开前面"的规则化。实测 U3：交叉 40 → **39**（hard 0、端点 0、转弯 2.89）。
收益有限的原因：U3 是**全星形拓扑**（4 条网各被 3 个元件消费），网与网共用同一批消费者 → 聚簇无空间。

**手画版复现实验（只调参数、不复刻坐标）**：把模板参数调到用户手画版的量级
（板—bb 间距 40→114、模块—bb 间距 250→166，环境变量 `V2_GAP_H`/`V2_GAP_V`）：

| 配置 | hard | 交叉 | 转弯 | 端点 |
|---|---|---|---|---|
| 默认（40/250） | 0 | 39 | 2.89 | 0 |
| **166/114（手画量级）** | **3** | 40 | 3.00 | 0 |
| 250/114 | 0 | 39 | 2.89 | 0 |

**结论**：**只调间距参数复现不了手画版**——模块—bb 间距缩到 166 后，我们的"面外横段带"没有足够
高度（staged 行会撞进元件带）→ 出现 3 处硬冲突。手画版的品质来自**另一套走线语法**：
横段贴在元件行下方的自由区、用长微斜（3-8°）吸收整段竖直位移——不是我们这套
"面外横段 + 竖落 + 收尾斜线"。要复现它，需要把"手绘语法"实现成一种走线模式（C 的核心内容），
而不是继续调参。

## 6.36 规则的"条件依赖"问题：车道规则加护栏（2026-11-10）

**用户提问**：这条严格规则化会不会在布局变化时失效？
**实测回答：会。** 行距压到 150（bb 上移到 235）时，固定车道 442.7 落进**面包板本体内部** →
穿板 2 处、交叉 35。原因：车道公式是"轨 y + 40 − 排名×24"，**轨 y 随布局变，车道就跟着跑**，

**修（护栏模式，与其它规则一致）**：
1. 车道先按规则算**偏好值**；
2. 再用 `allocHorizDown(偏好, 跨度)` 做**障碍避让 + 统一横段表**（9.6 间距）；
3. 若避让后仍穿件 → 返回 `null`，**调用方退回旧形态**（浅道/中段），不硬画；
4. 护栏生效的直接证据：行距 150 时车道自动变成 398.7/422.7/446.7/470.7（不再是 418/442/466/490），
   馈电相关冲突归零。

把板推进了这两根线的路径）。这不是车道规则失效，而是**另一条规则（对齐布局）的前提被破坏**。
→ 结论：规则要写成「**偏好 + 障碍避让 + 兜底 + 前提校验**」四段式；
每次布局参数变化都要跑边缘用例（行距 150/170/200、板位、3 脚/4 脚馈电）作为回归集的一部分。

## 6.43 用户手画的"跳线矩阵"隔离版（U3b，2026-11-12）：交叉 38 → 10

**存档**：`zcode-analysis/_evalt2`（29 条连接 / 5 元件）。指标：

| 指标 | 我们生成的（alignA） | **用户手画隔离版** |
|---|---|---|
| 硬冲突 | 8（仅方向提示） | **0（含方向提示也 0）** |
| 交叉 | 38 | **10** |
| 转弯/线 | 3.00 | **2.10** |
| 端点遮挡 | 0 | 7（全部"掠过 0px"） |
| 间距 <9.6 | 7 组 | 38 组（其中**只有 2 组是真违规 7.4px**，其余 9.5px 是取整） |
| 连接数 | 18 | 29（+11 根跳线） |
| 外框 | 696×516 | 721×605（填充率 33%） |

### 结构解码（三层分发）

1. **板脚 → 母线列**：`uno:A4→4t.a`、`uno:A5→5t.a`、`uno:GND.2→tn`、`uno:5V→tp`
   （板脚只出**一条**线，落到专用列/轨）；
2. **母线列 → 模块列**：`4t.b→17t.a`（SDA 母线）、`5t.b→28t.c`、`5t.d→21t.d`、`5t.e→14b.f` …
   **每个模块的每个网各有独立列**（mpu 27/28/29/30、rtc 21/22/23/24、oled 12/13/14/15）；
3. **列 → 轨**：`tp.25→30t.a`、`tn.24→29t.a`、`tp.19→23t.a`、`tn.10→12b.f` …
   每个电源列**一根**轨跳线。

→ 画布层面的线都很短，长距离连接改由 **bb 内部的列↔列跳线** 完成 → 交叉从 38 掉到 10。

### 两个可修的问题（都是系统性模式，不是随机）

1. **7 处端点"掠过"**：同一模块的 4 个网都放在**同一行**（rtc 全在 t.e、oled 全在 b.j）→
   一根线沿该行横走时会掠过兄弟孔。**规则：同模块同侧的网要错行**（a/b/c/d 分开）。
2. **2 处真间距违规（7.4px）**：`tn.24→29t.a × 5t.b→28t.c`、`tp.19→23t.a × 17t.e→22t.d`
   → 跳线矩阵也要过 `_spacing.js`，≥9.6。

### 由此固化的 4 条规则（"跳线矩阵"模板）

| 规则 | 内容 |
|---|---|
| **M1 母线列** | 消费者 ≥3 的网，设一条**母线列**（信号也适用）；板脚只连母线列一次 |
| **M2 一网一列** | 每个模块的每个网各占一列（列位容量允许时；实测 3 模块 × 4 网 = 12 列 + 母线 4 列 = 16 列，够用） |
| **M3 错行** | 同模块同侧的多列，孔位**错行**（a/b/c/d 或 f/g/h/i），避免沿线掠过兄弟孔 |
| **M4 列↔列跳线** | 跨列的连接用 bb 内部跳线完成，画布上不拉长线；跳线间距 ≥9.6 |

**容量结论**：本图 16 列（含母线）< 25 列上限；先前 `V2_ISOLATED` 失败是因为把"每元件每网"都塞进列还叠加了块/分隔约束（超容量），而不是隔离本身不可行。
