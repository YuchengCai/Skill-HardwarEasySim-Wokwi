# Generic Wiring — 未收录元件的通用兜底

> 当元件不在 `layout-cards/` 或元件目录里（首次使用、库外元件）时的**原则化兜底**。
> 核心：不靠「背每个元件」，靠「识引脚 → 分类 → 套通用规则 → 确定性走线」处理任何新元件。
> 首次使用跑通后，把学到的元件级偏好沉淀回 `layout-cards/` 并标 ✅（dev-workflow 闭环）。

## 步骤（模型按此推导，脚本负责确定性几何）

1. **识引脚**（拿到 type + pin 列表）
   ① 查 `references/arduino/index.json` / `detail/<type>.json`
   ② 缺 → 抓 wokwi-elements 源码 pinInfo（curl，见 SKILL.md source fallback）
   ③ 仍缺（库外元件）→ 先查 `placeholders/<name>/` 复用；没有则【暂停问用户品牌型号】→ 模型搜 datasheet 拿真实引脚 → `generate-part-placeholder.js` 生成（存 `placeholders/`，diagram.json 用 `chip-<name>`，wokwi.toml 声明 `[[chip]]`）

2. **按引脚功能分类**（不是按具体元件背）
   - 电源脚：VCC / 5V / 3V3 / VIN / GND
   - 数字/模拟 I/O 脚
   - 总线脚：I2C(SDA/SCL)、SPI(MOSI/MISO/SCK/CS)
   - 无源两端：电阻/电容（串联在信号链里）

3. **套通用接线规则**
   - GND → 负轨（面包板）/ 板子 GND（直连）
   - VCC → 按元件电压走:5V 消费者接正轨 tp(或板子 5V 脚);3.3V / VIN 消费者无专属轨,直连板子对应脚(3.3V / VIN),不接 5V 轨
   - 信号脚 → 就近的板子 GPIO（或对应总线脚）
   - 无源元件 → 串联在信号链里（如 LED 串限流电阻）
   - 颜色：电源线由脚本按电压家族自动分配（5V 红系 / 3.3V 橙系 / VIN 棕系 / GND 黑灰系，板→轨主线永远传统红黑，长线消费者按声明顺序领深浅档）；模型想覆盖时写非 red/black 的色值。信号线沿用模型写的颜色（绿/黄/蓝等）

4. **摆放**
   - 按功能分组（输入 / 输出 / 传感 / 显示），相关元件就近
   - 元件 > 8 或共享电源 → 面包板

5. **走线**（确定性，脚本已实现，与元件无关）
   - 板线分车道、轨线从相邻孔出线、最小 waypoint、就近端口、一孔一接
   - `chip-<name>` 占位符：wokwi 渲染成横向绿色 PCB——本体宽扁，焊盘在左右短边内侧竖直两列（DIP 逆时针序：左列 index 0..rows-1 上→下、右列 index N-1..rows 下→上）。左列引脚左出、右列右出，先离开芯片本体再走走廊（信号走统一走廊网格：min(芯片顶,板顶)-8 起向上每 8 单位一条、按板脚车道排；电源走「板底走廊带」：板底+16 起每 10 单位一条、主线占上两条槽位，从板子下方绕行与信号网格彻底分离）；模型只管 pins 顺序与网表，几何由脚本推导（间距 0.1"、内缩 4.5、顶距 5 单位为实测校准值）
   - 详见 `layout-rules.md` / `waypoints.md` / `breadboard.md`

## 首次使用后的闭环

跑通 + 用户确认 → 提炼元件级偏好 → 写入 `layout-cards/<type>.md` 并标 ✅

**沉淀什么（按端子语义边界，与 `intent-format.md` 的「开字段判据」同源）**：

- **多端子 / 易混淆元件**（按钮、开关、继电器、晶体管、电位器 3 脚）→ 沉淀**端子电气语义**：端子编号 + 导通关系 + 接法约束（例：pushbutton `1.l↔1.r / 2.l↔2.r / 按下通 1↔2`，信号与 GND 必须落在不同端子）
- **有极性 / 方向的两脚元件**（LED、二极管、电解电容、有源蜂鸣器）→ 只沉淀「极性 / 方向」一句，不写端子编号
- **普通两脚无极性元件**（电阻、瓷片电容、无源蜂鸣器）→ 不沉淀（netlist 已表达，写了是噪声）

判定标准：**netlist 能表达清楚 → 不写；netlist 表达不了、要靠元件内部物理结构才懂的 → 写**。端子语义随用随长，不预填所有元件。

**沉淀前的泛化闸门（三问，防散点化 / anti-copyback）**：

1. **类型级还是实例级？** 教训里出现具体 id（led1/btn2）→ 实例级，不写；抹掉 id 换成「这类元件」还成立 → 类型级。
2. **可迁移吗？**（替身测试）换个元件 / 换块板还成立吗？至少能套 ≥2 个不同实例。
3. **已覆盖吗？** 写之前 grep `layout-cards/` 和本文，查是否已有同义规则。

三问全过 → 才写入 `layout-cards/`；任一不过 → 属项目级一次性处理，不进 skill。
