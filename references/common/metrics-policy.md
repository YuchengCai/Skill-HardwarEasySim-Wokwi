# 指标政策（Metrics Policy）：哪些能优化、哪些只能当门槛

> 2026-11-13 定稿。起因：用户提出"把判据换成可计算指标，会不会又变成过度压指标"。
> 结论：**会，如果让软指标进入目标函数。** 因此把指标分三级，并禁止优化其中两级。

## 1. 三级指标

| 级 | 用途 | 允许做什么 | 本项目的成员 |
|---|---|---|---|
| **GATE（闸门）** | 一票否决，不可交易 | 必须 0 / 必须满足；不满足就回退 | 穿板、穿件、共线重叠、孔位冲突、方向非法；**端点唯一、端点不被异网压、束序不乱、平行间距 ≥9.6** |
| **BUDGET（预算）** | 只设上限，**不追求下降** | 超上限报警；不得为降它牺牲别的东西 | 交叉数、转弯/线、线长、外框面积、连接数 |
| **DIAGNOSTIC（诊断）** | 只用于归因 | 不参与优化、不进目标函数 | 交叉三分（①拓扑/②布局/③走线）、缝负载、嵌套层数、间距分布直方图 |

**铁律**：`BUDGET` 与 `DIAGNOSTIC` **不得写进优化目标**。优化器（人或模型）只能：
①把 GATE 修好；②让 BUDGET 不超上限；③用 DIAGNOSTIC 定位"超上限的原因"。

## 2. 为什么这样分

2026-11-09～11-12 的教训：
- 以"交叉数最小"为目标 → 反复调参空转（①类交叉是引脚次序决定的，压不下去）；
- 强行压交叉的实现（全隔离、翻侧、绕外圈）→ 交叉降了，但间距/端点/线数/面积恶化，
  **视觉上并没有更清晰**，只是数字好看。

反过来，真正改善视觉的改动，几乎都不是"降指标"：
- 同带下行（少 2 个转角、少 180px）：交叉 47→36，**同时**线更好读；
- 板让开走廊：交叉 54→47；
- 馈电四道嵌套：间距违规 10→7。

它们都是**形态规则**，不是"把某个数压小"。

## 3. 交叉数的正确用法

- 只统计三类：①拓扑不可免（引脚次序/带结构决定）、②布局可减（换序/换模板）、③走线错误；
- **只对 ③ 动手**；②要动布局（成本高）；①只记录、不追；
- 报告格式：`交叉 36 = ① 28 + ② 6 + ③ 2`，而不是单一数字。

## 4. 手改友好度（GATE 级，四项均为布尔）

| 项 | 判据 | 工具 |
|---|---|---|
| 端点唯一 | 同一孔/脚不被两根线占用（电源网内合法并束除外） | 孔占用检查 |
| 端点不被压 | 异网线不得掠过目标孔（同网并束豁免） | `_endpoints4.js`（吸附模型） |
| 束序不乱 | 沿出线边第 k 根 → 第 k 档车道/孔位 | 孔序分配 + `_spacing.js` |
| 最小间距 | 平行段 ≥ 一个孔距 9.6 | `_spacing.js` |

四项任何一项不满足 → **不合格**，不以"交叉更少"作为辩解。

## 5. 视觉清晰由谁定

- **人**：最终观感（"这版好不好看/好不好改"）；
- **模型**：给出**改动建议清单**（"把 A 组的三根线错行，可消除 3 处掠过"），而不是继续压数字；
- **脚本**：只做 GATE 判定、BUDGET 报警、DIAGNOSTIC 归因。

## 6. 对"约束求解"的约束

如果将来把启发式换成约束求解，**目标函数只允许包含**：
- 硬约束（GATE）作为可行性；
- BUDGET 作为**上界约束**（cross ≤ 上限），不是最小化项；
- 局部可修复性（例如"单线可移动即消除冲突"的对数）作为**最大化**项——
  它直接对应"用户拖几根线就能改好"，是唯一值得优化的软量。
