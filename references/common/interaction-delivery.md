# 用户交互与静态交付（序列4/文档45、27）

共享入口据此组织用户看到的回复。序列3 提供目标与接线事实，序列1 提供图与逐项验证结果，序列2 提供当前宿主能力。

## 实施顺序

1. 有明确请求直接处理；用户只说「开始吧」时，用一句话引导其描述功能或已有材料；用户主动问使用方法时再解释 skill。
2. 普通接线给可打开的静态图 + 按元件组织的接线说明，写到能唯一找到两端即可。成品线束已核实兼容时指出两端接口；分线、同名孔或观察方向会改变定位时补充芯位或排别。技术诊断留在开发记录。
3. 库外器件以实物接点为依据；替代图例丝印易误导时用按实物标注的占位件；交付同版本图与依赖文件，并标明影响使用的差异。
4. 按本次证据区分：**已核对成图 / 缺浏览器证据的文件 / 存在错接或缺线的诊断草稿**。后两种说明具体未核实或失败之处；可修问题先由工具修订；少量可手调的视觉细节才提示拖动线段中点或删后接回相同端点（不移动元件、不整体拖线）。静态交付到此结束。
5. 网页/插件都无法展示时，简述原因，让用户选**本地 SVG**或**纯文字接线**；用户决定后才生成 SVG；文字版直接列实物两端。用户直接拒绝画图时直接交文字。

## 展示与确认

- 展示同版图和文件时只问：「接线图清楚吗？还有疑问吗？」有疑问再定位、解释或改图。
- 纯绘图任务到此交付；用户明确只要文件时直接交文件。
- 已委托实物烧录时，在同一条消息说明确认后的具体动作（写哪版程序、目标板型、会替换现有程序），采用**合并确认**（一次确认覆盖「展示+烧录」）；用户有接线疑问先处理。
- 绘图或改图生成文件后应**主动尝试静态展示**；首次答复给出同版图和文件，或在确需授权/缺工具时说明下一步。功能仿真入口暂时隐藏。

## 交付状态（用词区分）

| 状态 | 含义 |
|---|---|
| 已核对成图 | 必需网络/锁定端点/几何检查通过，且有可用渲染或等效核对证据 |
| 缺浏览器证据 | 文件完整，但无静态预览；说明验证范围 |
| 诊断草稿 | 存在缺线/错接/硬冲突；列出具体问题，不得标为可照接 |

## 缺浏览器或用户选型确认

- 缺静态浏览器时按序列2 尝试可用途径（VS Code 插件/已授权 MCP/云端），都不可行时按用户选择交 SVG 或文字；常规绘图入口的编译/上传调用次数为 0。
- 用户对选型说「好的」时，只推进已委托步骤，不擅自扩大交付。
- 网页上临时调线或改图注后，必须同步最终下载件，再核对连接、路径与图注。

## 验收（文档45）

| 情景 | 从用户视角核对 |
|---|---|
| 新手只说「开始」/ 直接给完整引脚表 | 前者知道下一条可以发什么；后者直接拿图及接线说明 |
| 普通排针 / 已配套线束 / 两个同名 GND 指定一侧 | 三种说明分别能找到引脚、接口、指定物理孔；无需了解内部检查步骤 |
| 实物 I²C RFID 与库中图例不同 / 自定义件缺文件 | 对照图与文字能指出实物端点；缺文件识别为未完成并修复或交待缺项；已知错接的草稿不能标为可照接 |
| 缺静态浏览器 / 用户对选型说「好的」 | 前者按序列2 试静态途径，均不可行时按用户选择交 SVG/文字；后者只推进已委托步骤；两种情况功能仿真/上传调用次数均为 0 |

最后从非开发者视角抽查一根线：只看交付物，能否说出实物两端并在图上找到它们。
